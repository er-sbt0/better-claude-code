### What the code decided that the doc had not

- **`turn.started` / `turn.finished` are raw events.** §8's vocabulary had no
  turn concept, and a run and a turn are different lifetimes. Cost lives on the
  turn, because that is the granularity the provider reports.
- **`raw.unclassified` is a normal outcome, not an error.** Hook events land
  there today. It is what makes §7's degradation invariant mechanically
  checkable, and a test asserts every line is classified, preserved, or counted
  as transient.
- **The normalizer is deliberately not abstract.** No trait, no adapter enum —
  §5's rule. The shape will be extracted from the diff against Codex.

### The three findings that change decisions, not just details

- **Both agents ship sandboxes now.** Claude Code 2.1.269 has filesystem
  confinement and network egress control, reached from a subprocess driver via
  `--settings`. Codex already had one. §12 option B was sized as "the one
  capability a competitor cannot trivially copy"; that premise is gone for both
  agents we support first. The doc now re-prices it as an
  integration-and-uniformity argument. **This is the biggest open re-think.**
- **Claude Code grew a supervisor and worktrees.** `--bg`,
  `claude agents --json`, `attach`/`logs`/`stop`, and `-w/--worktree`. §13 and
  §17 assume we build both. Owning them is still defensible on agent-neutrality
  grounds — Codex has neither — but it needs to be a decision.
- **Usage lives in three non-agreeing fields.** `result.usage` covers the main
  model only and misses side-model spend; `modelUsage` reconciles exactly to
  `total_cost_usd`. Wrong choice here produces numbers that are quietly wrong
  forever.

## Suggested next action

**The SQLite event log, then the process driver.** That is the rest of the
headless spine, and both are specified well enough to write now. Order matters
for one reason:

> **Decide the Review attribution mechanism before the process driver exists.**
>
> "Reasoning attached to the hunk that produced it" is asserted in §1, §7 and
> §10 and specified nowhere. Matching hunks to `Edit` calls by string comparison
> fails exactly where it matters — a file edited three times, a `Write` later
> edited, a formatter, a `Bash` mutation with no tool record.
>
> The robust version falls out of worktree-per-run: snapshot the worktree into a
> shadow commit after every mutating tool call, via a separate `GIT_INDEX_FILE`
> and `git commit-tree` onto a private ref, so HEAD and the user's index are
> never touched. Attribution is then blame against that synthetic history —
> hunk → shadow commit → `seq` → blocks. It catches formatter and `Bash`
> mutations because it records outcomes rather than intentions, and it gives
> §20.5's run replay for free.
>
> This makes "commit after every mutating tool call" a requirement *of the
> process driver*, which is why it cannot be decided later.

Still queued behind that, unchanged in priority:

- **Install Codex and record its fixtures.** Largest remaining debt; unblocks
  the V2 abstraction. Do not generalize the normalizer until it exists.
- **Build the minimal workspace MCP server.** §6 source 3 is called the spine of
  the semantic model and has never been demonstrated once. Also the only way to
  record the `--permission-prompt-tool` and `workspace.report` fixtures.
- **Spike the WebKitGTK performance budget** (5k-block virtualized feed +
  CodeMirror + xterm) before committing to Tauri, per §4. A day, and it is
  cheaper now than after the runtime assumes the stack.
