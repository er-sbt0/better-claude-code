### What building decided that the doc had not

- **The writer assigns `seq`, not the store.** An event has to be addressable
  (§7) the moment the normalizer produces it, before it is durable, or the UI
  cannot render a streaming run. Consequence: a resumed run *must* seed its
  normalizer from `last_seq`. The log rejects a non-advancing `seq` so that
  mistake fails loudly instead of interleaving with history.
- **`seq` gives ordering, not gap detection.** §8 claimed both; they do not
  survive together. Replayed events consume a `seq` and then deduplicate away,
  so holes are the normal result of a resume. §8 corrected.
- **Run metrics are a projection, not columns.** §14 lists cost and tokens on the
  run entity; §8's rule makes them recomputable, so they are a query. A fixture
  test asserts they still reconcile, which is how we find out the provider
  changed its accounting — instead of a user finding out from an invoice.
- **Attribution needs a root snapshot at `seq 0`**, taken after §13's
  post-create hook and before the first tool call. Otherwise every file the hook
  wrote is attributed to the run's first `Edit`.

### Three traps that are easy to re-introduce

- **Review must run a second query for deleted hunks.** `blame` only sees lines
  that survived; deletions come from `removed_at` (the pickaxe). A UI that only
  blames will silently show no attribution for removals, which looks like
  working software.
- **Never benchmark durability on `/tmp`** — it is tmpfs here. The first
  `synchronous` measurement reported FULL and NORMAL as identical because
  nothing was ever fsynced. The example now refuses to run there. Real numbers:
  1.2ms/commit FULL vs 0.04ms NORMAL on ext4/NVMe; FULL was kept.
- **Snapshots serialize per worktree.** The shadow index is one file. Parallel
  subagent tool calls would degrade attribution to "one of these calls" — and
  this is untested, because no recorded fixture has subagent traffic.

## Suggested next action

**The process driver.** It is now the only missing piece of the headless spine,
and everything it needs exists and is tested. It is wiring, not design:

- spawn Claude Code with §5's verified flag shape, **assigning** `--session-id`
  so the run row has its `providerSessionId` before the process starts (§14)
- create the worktree, run the post-create hook, *then* `ShadowHistory::begin`
- feed each stdout line to the normalizer; append its events in one transaction
  per line, so a crash never leaves half a provider message in the log
- **snapshot after every `tool.completed` that mutated something** — this is the
  requirement §13.1 exists to impose on the driver
- on resume, seed the normalizer from `EventLog::last_seq`, or every append
  fails `SeqNotMonotonic`
- at startup, reconcile `EventLog::running_runs` — every one of them is a run
  whose process died with the app (§8's crash recovery)

The one thing in it that is *not* wiring: the driver is the first component that
has to decide what "a tool call that mutated something" means. `tool.completed`
does not say. Snapshotting after every completed call regardless is the honest
default — an unchanged tree costs one `git add -A` (~25–40 ms) and commits
nothing — and it is the only version that catches `Bash`.

Still queued behind that, unchanged in priority:

- **Install Codex and record its fixtures.** Largest remaining debt; unblocks the
  V2 abstraction. Do not generalize the normalizer until it exists.
- **Build the minimal workspace MCP server.** §6 source 3 is called the spine of
  the semantic model and has never been demonstrated once. Also the only way to
  record the `--permission-prompt-tool` and `workspace.report` fixtures.
- **Spike the WebKitGTK performance budget** (5k-block virtualized feed +
  CodeMirror + xterm) before committing to Tauri, per §4. A day, and it is
  cheaper now than after the runtime assumes the stack.
